# GitHub-native PR risk and review evidence

`github-pr-risk-review.cjs` is a read-only evidence collector. It checks a bounded, fully paginated GitHub PR file list and patch set, review decisions, required check runs, the Required PR gate's associated Actions run, current `main`, the active ruleset, and a pinned workflow inventory. It binds its observation to the repository and owner IDs, PR number, exact head and base SHAs, and a SHA-256 digest of the complete normalized diff. It takes two complete snapshots and rejects a mismatch.

The risk classifier uses a conservative allowlist. Only ordinary documentation and constrained CSS are eligible for low-risk observation; test code is not allowlisted because CI executes it. Authentication, security, permissions, secret handling, databases and migrations, infrastructure, deployment, production, release, grading, grounding, merge policy, workflow changes, known workflow side effects, and unknown paths cannot be classified as low risk. Renames are evaluated using both old and new paths. The workflow inventory is pinned to protected `main` at `c2531f0ef07c9806f307ce311b1bc9109fcf051b`; a changed, added, removed, or unknown workflow blocks observation until a separately reviewed inventory update. This PR adds CI wiring, so this verifier intentionally cannot classify its own PR as trusted.

The REST review-comments endpoint does not provide authoritative resolved-thread state, and issue comments may contain material findings, so any inline comment, PR discussion comment, or nonempty review body causes the collector to fail closed. Review approvals must be from a human collaborator and be attached to the exact current head. Checks must match the configured GitHub Actions issuer and exact head, and the Required PR gate must link to a completed successful `pull_request` run associated with this PR and base.

This collector is **observation only**. It does not authorize a merge and is not connected to the automatic-merge evaluator. A clean result is not proof of authenticated specialist execution, user authorization, atomic target/base protection, or complete GitHub review-thread resolution. The automatic policy remains disabled and returns `trusted_live_verification_unavailable`.
